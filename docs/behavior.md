# 行为逻辑说明

## 坐标与单位

游戏内部坐标以厘米为单位。脚本中的距离常量也按厘米写：

- `25000` = 250m
- `22000` = 220m
- `17000` = 170m

## 威胁判定

脚本把“富敌”定义为黄色 `Drop` 数量大于 10 的敌方存活实体。

`Drop` 对应游戏实体字段：

```js
death_reward_preview ?? death_drop_coins ?? 0
```

不要用 `coins` 字段判断富敌。`coins` 可能表示账户/总金币类数值，不是画面黄色 `Drop` 标签。

170m 紧急逃离使用更宽的“近身威胁”定义：

- 黄色 `Drop` 大于 10。
- 黄色 `Drop` 不超过 10，但脚本在最近 10 秒内观察到该敌人坐标移动过。

低 `Drop` 敌人的移动历史按敌方 `user_id` 记录，只保留最近看到和最近移动时间。

## 规避逻辑

- 富敌在 250m 内：选金币时排除会靠近富敌 220m 内的目标。
- 富敌在 220m 内：主动拉开距离。
- 近身威胁在 170m 内：两阶段撤离。前约 1.5 秒纯反向拉开；同一敌人持续逼近后，转向远离威胁的安全金币锚点顺路收币。锚点到达或超时后排除当前点换下一颗，没有下一颗则回纯反向，避免在同一金币点原地转圈。显示暗红色呼吸 HUD。
- 常态不会因为敌人仅仅靠近就点击“离开”；但受伤、体力上限、运行卡住或明确网络异常会触发离开/恢复。

## 连线指示

- 金黄色轻微发光线：当前将要前往的目标。金币/右键坐标会指向目标点，逃离时会指向反方向的临时逃离点。
- 蓝色轻微发光线：实时视野 500m 内 `Drop` 大于 0 的敌人。
- 红色轻微发光线：170m 危险距离内 `Drop` 大于 0 的敌人。

`Drop` 为 0 的敌人不绘制蓝线或红线，避免画面被低价值实体干扰。

连线层是透明 canvas（画布）覆盖层，使用 requestAnimationFrame（浏览器帧同步）绘制，不带全屏滤镜或实体背景，不会接管鼠标事件。

为避免卡顿，连线层不要用 `innerHTML` 反复重建 SVG DOM。当前实现会在同一个 canvas 上清屏重画，并把设备像素比限制在合理范围内。

连线器和红色倒三角先复用游戏原生 `worldToScreen`（世界到屏幕）/`viewParams`（视图参数）换算到全屏游戏 canvas，再减去 HUD 右侧场景区 root 的左上角作为透明 canvas 内部坐标。不要自己估算全屏中心或 HUD 中心，否则左侧官方面板、缩放和相机中心都会让 overlay 出现系统性偏移。

掠夺版追击/开火时仍保留目标与威胁连线；透明 canvas 不参与鼠标事件，实际开火才允许更新准星。

## HUD 性能策略

HUD 信息块只使用普通半透明 `rgba` 背景。不要使用 `backdrop-filter`（背景滤镜）或 `-webkit-backdrop-filter`（WebKit 背景滤镜），避免毛玻璃造成额外渲染开销。

## Drop 排行榜

HUD 控制区内的 `DROP RADAR`（掠夺版显示为 `RAID TARGETS`）常态每 10 秒刷新一次，展示全场黄色 `Drop` 数最高的 5 名玩家。脚本刚进入游戏、首次识别到当前玩家实体后，会在 3 秒后额外刷新一次，避免刚登录时排行榜还停留在空数据。

数据来源会合并两路：

```js
death_reward_preview ?? death_drop_coins ?? 0
state.minimap.points[*].d
```

`state.entities` 可能在不同同步状态下表现为可见实体或较完整实体列表；`state.minimap.points` 的 `u/d/x/y` 会覆盖全场小地图点，其中 `d` 是全场 Drop。排行榜按同一个用户合并两路数据并取更高 Drop。不要用 `coins` 字段做排名。

用户名优先读取实体 `name`，其次读取 `state.userNames`。如果没有真实用户名，排行榜会显示未知用户，但不会把纯 ID 或 `User id` 当成可复制用户名。

点击排行榜里的用户名只复制到剪贴板，不再驱动追杀状态。复制优先使用浏览器 Clipboard API（剪贴板接口），失败时退回到临时 `textarea`。

## 两种 PC 构建

2.0.0 起，桌面端由同一源码在构建时生成两个互斥 userscript，用户只安装其中一个：

- `grasp-rat-gold-runner.user.js`：游走拾荒。不会主动开火，执行安全短路线、富敌规避和巡航躲弹。
- `grasp-rat-raider-runner.user.js`：杀敌掠夺。没有合格目标时同样拾荒；有合格目标时进入追近→锁定→开火→等待掉落→拾取闭环。

旧的“追杀”“临时交战”“自动攻击”按钮和攻击列表已从 PC HUD 移除。核心能力没有叠成更多开关，而是由所安装的构建决定。

## 掠夺候选与火控

掠夺版按以下规则筛选目标：

- 存活、有 Drop、未处于无敌状态、500m 内。
- 连续静止至少约 8 秒的目标可进入挂机候选。
- 活跃目标只有在自身 HP 至少 45，且目标 HP/Drop 明显占优时才作为收割候选。
- 估算击杀发数、追近时间、拾取时间以及 5 秒/1 小时体力预算，再与最佳金币路线做同量纲收益比较。
- 新机会必须比当前机会高约 15% 才切换，降低追一半突然掉头。
- 追近时对目标速度做短预判；进入约 140m 后才开火，150m 是硬射程。
- 火控沿用 5-8 发覆盖、每发约 0.5 体力并保留 2 发余量的预算规则。
- 目标失去资格、目标优势反转、自身 HP≤25、单次交战累计掉血达到 18 或体力只剩退出储备时止损离开。
- 第三方近身威胁优先于当前掠夺目标；击杀目标消失后在最后位置等待约 1.2 秒，并在约 28m 范围优先接管新掉落。

## 受伤离开逻辑

游走拾荒模式下，如果当前 HP 小于上次记录的 HP：

1. 停止移动。
2. 点击页面“离开”按钮脱战。
3. 停止脚本移动状态。

PC 端脚本处于“停止”模式时，仍会通过 HUD 状态刷新保留 HP 监控。停止态首次看到当前玩家实体时记录 HP 基线；之后只要 HP 低于该基线，就立即点击“离开”脱战。该逻辑只负责保命，不会恢复拾荒、掠夺或任何移动控制。

## 1h 体力限制离开逻辑

脚本会每秒读取游戏左侧官方 `.side` 面板文本。如果左侧栏出现 `1h体力限制`，立即点击“离开”退出游戏。

这个检测不依赖金币巡航是否启动；只要 userscript 已经加载并找到游戏变量，就会生效。它不会读取聊天区，避免被历史聊天消息误触发。

## 自动重连

PC 端自动重连**默认关闭**，需显式开启。开启后有两种授权模式：`NAVIGATE_ONLY`（默认，只把用户带到授权页，绝不自动点“允许”）与 `STRICT_AUTO_CONSENT`（仅当授权页契约精确匹配时自动允许）。授权/登录动作都在未知结构下 fail closed，失败进入明确终态。2.0.0 另加运行看门狗：移动约 4.5 秒无进展先强制重规划，连续卡住、玩家实体持续缺失、明确断网提示或可信服务器 tick 约 12 秒不刷新时，走离开；只有重连开关已开启时才继续自动重连/刷新。离开按钮失效时最多自动刷新 2 次，之后停住等待人工处理，避免刷新风暴。完整安全模型见 `docs/reconnect-security.md`。

## 金币路线规划

金币巡航不是单纯最近优先，也不是只看单个目标。脚本会先生成安全金币候选池，再比较“单个高价值/近距离金币”和“金币团连续路线”的单位时间收益。

路线评分综合：

- 金币金额
- 连续多个金币之间的路程估计
- 周边金币密度
- 目标点距离富敌的安全程度
- 每段路径中点距离富敌的安全程度
- 是否需要明显掉头
- 当前目标稳定性偏置
- 路线总长软折扣（全程超过约 300m 后压分）
- 首段路程偏好（第一颗金币在约 120m 内不打折，超过约 350m 压到约 0.28）

路径安全按整条线段判定（§5.2）：金币目标与路线每段都计算“玩家到目标/整段路径”到最近威胁的最近距离，而不只查端点和中点；敌人在线段 1/4、3/4 等中部位置也会被判危险并避开。

金币密度高时，路线会规划更多连续金币点；金币稀疏时，只规划较短路线或单点目标。这样会优先吃一片金币团里的顺路金币，减少吃完一个点后重新掉头找下一个点。

贴近当前金币约 160cm（`COIN_REACHED_CM`）后先等约 600ms 确认入账；若金币迟迟不消失，会最多做 2 次小幅正交轻推；仍不消失则把该 `drop_id` 临时黑名单约 8 秒并重规划，避免卡在原地（§5.7）。金额缺失/非法的掉落不会进入候选池（§5.6）。

默认约每 1.8 秒重规划一次。若当前路线仍然有效，只有新路线评分明显更好才切换；当路线上的当前金币消失后，会立即允许重新评估剩余路线。

## 右键手动坐标

在游戏画布上点击鼠标右键时，脚本会读取游戏页面当前 `pointerWorld` 坐标，并设置为手动目标。

手动目标行为：

- 如果脚本未启动，会自动启动。
- 安全逻辑仍然优先，包括受伤离开、体力、死亡、170m 敌人规避。
- 安全时会暂停金币规划，优先前往右键坐标。
- 掠夺版右键设置目标时会结束当前追击；安全逻辑仍然优先。
- 到达目标约 160cm 范围内后，自动清除手动目标，并恢复金币规划。

## 移动策略

脚本保留八方向移动，但会按目标斜率选择：

- x 方向占优：横走
- y 方向占优：竖走
- 两者接近：斜走

这样避免一直 45 度斜线前进。
